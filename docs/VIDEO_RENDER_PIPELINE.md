# Video render pipeline

Browser-first export uses **Mediabunny 1.63.0** and WebCodecs. Installed declarations were checked against [writing files](https://mediabunny.dev/guide/writing-media-files), [media sources/backpressure](https://mediabunny.dev/guide/media-sources) and [WebCodecs](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API). The package is recorded in package-lock.json. It provides container muxing; encoded chunks are never concatenated into a pretend MP4.

1. Validate eligible connections and requested transparency.
2. Use `canEncodeVideo` for AVC and VP9 at the selected dimensions/FPS/bitrate. Reject an unavailable requested format and explain alternatives.
3. Enable temporary export detail; await every registered RuntimeModel export preparer at High and its mounted result. Wait for React paint so wires/selection hiding are committed.
4. Clone scene object transforms while sharing cached component geometry, textures and environment. Retain component groups and lights; omit editor grid, proxies, HTML, selection wireframes, diagnostic overlays and controls. Clone wire geometry and owned focus materials so export draw ranges and highlights cannot alter editor state.
5. Render a dedicated camera and WebGL canvas at native 1920×1080, 2560×1440 or 3840×2160. A separate 2D composition canvas draws those pixels and a rounded connection card with the real wire color, ordered connection number, source/destination component names and physical pin names, plus a matching opening title. No viewport upscaling or HTML screenshot is involved. Preview uses 1280x720 and Medium CAD; final export always prepares High detail at the requested native resolution.
6. Call `CanvasSource.add(N/FPS, 1/FPS)` sequentially, awaiting its backpressure promise. Request a keyframe every two seconds. AVC is muxed with `Mp4OutputFormat({fastStart:'fragmented'})`; VP9 uses WebM. Audio is absent. Default bitrate is 12 Mbps, or 40 Mbps at 4K.
7. Close the source, finalize the container, then decode the first frame in a browser video element to validate native dimensions and nonzero duration before normal download. Browser tests additionally decode the entire video with FFmpeg and inspect ffprobe metadata.

Backgrounds use the same dedicated WebGL scene for live sequence preview, PNG frame rendering and encoded video. Solid backgrounds are Three.js scene colors. Gradients use one small sRGB screen-space texture created when background settings change, so the camera cannot rotate the gradient. Captions use a contrast palette selected from the configured background and are drawn into the 2D composition canvas. See [background settings and color handling](VIDEO_BACKGROUNDS.md).

Only current WebGL/2D frame buffers and bounded encoder queues hold raw images. No frame array is accumulated. PNG fallback uses sequential PNG blobs and a ZIP pass-through entry per frame; it retains encoded ZIP chunks, not RGBA frames. Ordinary encoded downloads have a 512 MiB limit with an explicit error. PNG ZIP has the same limit and is not offered as an unbounded long-film path.

Optional direct file export uses the browser File System Access picker and a Mediabunny StreamTarget with 4 MiB chunks and positional writes. It avoids retaining the final movie in JS memory. Source `add` promises propagate muxer/writer backpressure. File abort is attempted on failure/cancellation. The picker must be invoked from the user's click. Direct files are finalized before close but are not reread for automatic browser decode validation; normal downloads receive that validation.

Finally, owned wire/marker geometry, materials, rendering context and canvases are released; shared model-cache resources remain owned by the existing editor. Original camera, project, selection and animation session are untouched. Temporary export quality is restored in `finally`, including exceptions. An already-submitted GPU/encoder task can finish before cancellation is observed. The editor remains interactive, but a running export uses a fixed scene snapshot; resource preparation and rendering still consume the device GPU.

Compatibility: modern secure-context Chromium is the acceptance environment. Codecs vary by browser, driver, resolution and FPS. WebM is offered explicitly, never silently substituted or misnamed. MP4/H.264 and the current WebM export are opaque. Transparent export requires PNG frames. No MediaRecorder/captureStream or real-time scheduling is used. Browsers without WebCodecs can still export PNG ZIP. 4K may be slower than playback. GPU context allocation failures and encoder failures are reported; GPU memory availability cannot be measured reliably. Download buffers are capped, but overall device memory use is not guaranteed by that cap.
